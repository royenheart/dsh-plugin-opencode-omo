# 5. Risks

- **Core-loop patch maintenance.** `assistantPrefill` is still not upstream; the patch may need rebasing when the loop, header, or token-meter internals change. The plugin's capability probe keeps stock hosts on the fallback, so a missing patch degrades rather than breaks.
- **Synchronous session reads.** Prompt assembly uses `session.snapshotEvents()`; 0.2.1 marks that reader deprecated and prohibits new production calls. A projection-based plan/step read is the follow-up.
- **Token accounting is pressure-only.** The prefill is priced in token pressure but has no dedicated `contextBreakdown` bucket; breakdown still reports system/tools/message surface components.
- **Per-child role identity.** dsh child descriptors still do not carry the omo role id, so named-role tool restrictions are maintained by the plugin's schema filter and `tools/pre-execute` mirror rather than an official per-child field. Child sampling still inherits the session model; primary-role sampling defaults are applied.
- **Optional LSP packaging.** The optional module catches missing LSP packages/server and keeps the preset bootable, but an installed package set with a missing `typescript-language-server` leaves the `lsp_*` tools without a provider until the server is installed.
- **Browser interaction not clicked through.** The bundle, settings namespace, preset roster, and session creation were verified against a real host; the role picker and Role Settings controls were not exercised with a configured model/API key.
- **Settings merge semantics.** `settings.update` merges nested role objects; fields the UI does not currently edit (`maxSteps`, `ultrawork`) are preserved rather than cleared. New editors for those fields should use path mutations or explicit clears.
- **Patch test scope.** The loop regression runs in the harness workspace; the patched path was not exercised in a live web profile because the installed verification host was the unpatched npm `0.2.1-rc.2` build.
